## 二、供电架构

### 2.1 电源树
```text
Type-C VBUS 5V ──[USBLC6 ESD]──┬── CC1/CC2 各 5.1k 下拉（UFP，缺它则 C 口不供电）
                               ├── D+ / D− → GPIO12 / GPIO13（ESD 阵列）
                               └── CL4064M (U4) ──[R_PROG 5k]── 200mA 恒流恒压 → BAT
                                                                        │
   [2P 电池座 J2]  1S 锂电 3.0~4.2V  ────────────────────────────────────┘
                                        │
                                        └── LN3440 (U2) 升降压，1.7MHz
                                              ├─ L 2.2µH（L1~L2）
                                              ├─ Cout 2×22µF + 0.1µF
                                              ├─ FB 200k/1.16M → 3.40V
                                              └─ MODE=GND（PSM）／EN=VINA=VIN（常开）
                                                        │
                                            3.40V 骨干轨（≈3.35~3.45V）
                                              ├─ 磁珠 + 22µF + 0.1µF → ESP32-C6-MINI-1
                                              ├─ 0.1µF×2 + 1µF → LIS3DH
                                              ├─ 1M/1M 分压 + 100nF → GPIO2 ADC（电池电压）
                                              ├─ WS2812B ×1（+1 DNP）**常供、无门控**
                                              ├─ 4.7k×2 → I2C 上拉（GPIO14/15）
                                              ├─ 100k×3 → OPEN/CLOSE/RTCIO 三路按键上拉
                                              └─ 100k → CHRG 上拉；100Ω → 外部座 VCC
```
> **USB 5V 不进 DCDC 输入**：VBUS 只走充电器，3.4V 轨永远由电芯供给。理由有二——
> ① LN3440 的 VIN 绝对最大只有 **6.5V**，而 VBUS 在劣质适配器/线缆上很脏；
> ② 5V 与 3.4V 若共用一个节点，充电电流与系统负载会在电芯端叠加，充满判定与线损都变复杂。
> 副作用：**电芯亏空时插上 USB 不能立刻工作**，要先充到 UVLO（约 2.1V）以上——本板可接受（与 §9.2 #14 一并实测）。

### 2.2 充电：CL4064M（线性，200mA）
| 项 | 取值 | 依据 |
| --- | --- | --- |
| VCC | Type-C VBUS 5V（4~12V 工作，16V 抗浪涌） | 5.1k CC 下拉保证标准源只给 5V |
| **R_PROG** | **5kΩ 1% → 200mA** | I(mA) ≈ 1000/R(kΩ)；覆盖 200mAh(1C)~500mAh(0.4C) 全档 |
| 耗散 | (5−4.2)×0.2 = **0.16W** → SOT-23-5 温升 ≈40℃ | 若改 400mA 则 0.32W → 温升 ≈80℃，逼近 135℃ 热调节 ⇒ **不建议再加大** |
| 涓流 | V_BAT < 2.9V 时约 25mA | 深放电电芯的复充保护 |
| 终止 | 充电电流降到设定值的 **3/10** 时终止；回到 4.1V 附近自动再充 | 系统平均电流 ≈0.6mA ≪ 20mA 终止门限，**不会干扰终止判定** |
| CHRG | 开漏：充电时拉低，其余高阻 | ① 100k 上拉到 3.4V → **GPIO19 读充电态**；② 经 1k 驱动 D3 做"充电中"指示灯（**不依赖固件**） |
| 静态 | VCC 在时 35µA；**无 VCC 时电芯漏电 <1µA** | 待机档预算里按 <1µA 计（USB 常年不插） |
| 电芯自带保护板 | **必须**（过充/过放/过流） | 本板不做二次保护，见 §2.4 |

> ⚠️ **VBUS 被拉到 9V/12V 时会发生什么**：用 A-to-C 线接 QC/BC1.2 类老式快充头，VBUS 可能升到 9V/12V。
> CL4064M 的工作上限 12V、抗浪涌 16V ⇒ **不会损坏**，但耗散升到 `(9−4.2)×0.2 ≈ 0.96W`，
> 芯片会靠 **135℃ 热调节自动降流**保命。⇒ 现象是"用某些充电头会充得很慢"，属正常保护，不是故障。
> ⚠️ **CHRG 上拉到 3.4V 的前提**：VCC 不在时 CHRG 高阻，100k 上拉把该脚抬到 3.4V。开漏输出的
> 漏-衬底二极管此时反偏，理论不漏电；**仍列 §9.2 #3 实测**（判据：无 USB 时 CHRG 支路 ≤1µA）。

### 2.3 3.40V 轨：为什么必须是升降压
电芯电压 **3.0~4.2V 跨在 3.4V 两侧**——单用 Buck 会在低压端掉出稳压，单用 Boost 会在高压端失控。
单电感升降压是这个输入区间的正解，且 LN3440 的 **Iq 只有 16µA**，对 µA 级待机档是可接受的代价。

| 项 | 定稿 | 依据 |
| --- | --- | --- |
| 输出电压 | **3.40V**（R1=200k / R2=1.16M，1%） | 见下「为什么不是 3.3V」 |
| MODE | **接 GND = PWM/PSM 自动切换** | 本板常态只有 0.6mA 级负载，强制 PWM（MODE=1）会把几十 mA 的无谓损耗灌进来 |
| EN | **接 VIN（常开）** | 本板无常开负载需门控；"关机"由深睡实现（§2.4） |
| VINA | 100Ω + 1µF 退耦后接 VIN | 控制级与功率级解耦，避免开关噪声污染反馈 |
| 电感 | **2.2µH / 饱和 ≥1.5A** | 手册推荐 1.5~3.3µH；峰值电流按最坏点 VIN=3.0V、IOUT=0.5A 折算约 0.68A |
| 输出电容 | **2×22µF + 0.1µF** | 手册推荐 22µF；**翻倍是为射频突发**（见下注） |
| 反馈分压电流 | 3.4V / 1.36MΩ ≈ **2.5µA** | 直接进待机档预算，故取大阻值档 |

> **为什么不是 3.3V**：WS2812B-2020-V6 的 **VDD 下限是 3.3V**，而本板轨若定 3.3V 则零余量。
> 3.40V 名义（含 1% 分压与 FB ±2% 容差后 ≈**3.35~3.45V**）在两端同时留出余量：
> 下端对 WS2812 的 3.3V 留 0.05V，上端对模组 3.6V 绝对最大留 0.15V。与驱动板同口径。
>
> ⚠️ **PSM 的瞬态代价**：省电模式（PSM）环路响应慢，而 ESP32-C6 的射频突发是**几百 µs 的电流阶跃**
> （峰值 200~300mA）。输出电容翻到 44µF 就是为这件事——把"DCDC 反应过来之前"的那一段扛住。
> **实际跌落深度必须实测**（§9.2 #1），判据：突发期间轨底 **不低于 3.3V**。

### 2.4 电源纪律
1. **无常开负载、无门控开关**：WS2812 与 LIS3DH 都常供电——前者静态 ≦1µA、后者待机 0.5µA/low-power 10Hz ≈4µA，
   对 ≈35µA 的待机档是可接受的；**加门控要占 GPIO 与器件，换不回成本**。
2. **不设硬开关**："关机" = **深睡（≈35µA）**，靠 OPEN/CLOSE/外部接点唤醒。
   物理断电靠**拔电池座**（运输/长期仓储）。LIS3DH 在深睡期间继续按 ODR 采样，也是唤醒源之一。
   > 依据：500mAh 电芯在 35µA 下可放 **≈1.6 年**，与自放电同量级 ⇒ 关机档与"断电"的差别对用户无意义。
3. **不板载电池二次保护**：过充/过放/过流由**电芯自带保护板**承担，本板只做充电管理。
   ⇒ **必须写进说明书**：只能配**带保护板的 1S 锂电**。
4. **电池座无防反接**：反插会把电芯反压到充电芯片与 DCDC 上。三重兜底：丝印标 +/−、座子选带防呆键的型号、上电前万用表确认。
5. **不需要 TVS**：本板最高电压就是 **4.2V**（电芯满充），与驱动板的 25.2V 母线是两个世界。

> ⚠️ **LP 域是本板最紧的资源**：只有 GPIO0~7 支持 **ext1 深睡唤醒**。本板的四个唤醒源
> （两键 + 外部接点 + 运动）**全部必须落在 LP 域**，而 GPIO0/1 被晶振占用、电池 ADC 又只能落在
> ADC1（GPIO0~6）——**这四路分完，LP 域一个不剩**（GPIO7 已是最小冗余）。
> 后续要加唤醒输入，只能与现有四路**并线**（固件从"哪一路在动"反推），或把某一路挪到 HP 域并接受它不能唤醒深睡。

### 3.1 三类特殊引脚（Strapping / ADC1 / RTCIO）
| 类别 | 范围 | 关键约束 |
| --- | --- | --- |
| **Strapping** | GPIO4/5/8/9/15 | 复位释放瞬间锁存；**未拉高的两个必须由外部电路保证**：GPIO8=10k 上拉、GPIO15=I2C 的 4.7k 上拉；**不得加消抖电容**（消抖只能做在固件里） |
| **ADC1** | GPIO0~6，7 路，无 ADC2 | 本板只用 1 路（GPIO2 电池）；GPIO0/1 被晶振占用，实际可用 5 路 |
| **RTCIO（LP 域）** | GPIO0~7，8 个 | 深睡期间仍供电：**唯一支持 ext1 唤醒**、可保持电平、可复用 LP 外设 |

### 3.2 Strapping 脚上电电平核查表（ESP32-C6 共 5 个）
| 脚 | 上电锁存电平 | 由谁决定 | 判定 |
| --- | --- | --- | --- |
| GPIO4 | 0 | **CLOSE 按键的 100k 上拉**（未按下 = 高） | ⚠️ 见下注 |
| GPIO5 | 0 | 外部座的 100k 上拉（未接设备 = 高） | ⚠️ 见下注 |
| GPIO8 | 1 | **10k 上拉**（被动） | ✅ **严禁加下拉、严禁接任何会拉低的负载** |
| GPIO9 | 1 | **芯片内部 45k 上拉**（数据手册默认 Pull-up） | ✅ BOOT 按键直连 GND；外部只接 SW3 |
| GPIO15 | 高 | **I2C SCL 的 4.7k 上拉**（被动） | ⚠️ 仅在选择 JTAG 信号源时参与判定，默认不影响启动 |

> ⚠️ **GPIO4/GPIO5 是本板唯一要盯的一对 strapping 脚**：它们默认应为 0，但本板各挂了一个 100k 上拉 ⇒
> 上电锁存到 **1**。按 `docs/doc.md` §4.2 的核查表，这两个脚只影响 **JTAG 信号源**与 **SDIO 采样沿**（本板都不用）、**不参与 boot 模式**，
> 所以**是安全的**——但必须写死这条结论，避免后人误加下拉或误改成"上电必须为 0"的接法。
> ⚠️ **GPIO8 的纪律照抄驱动板**：它的 strapping 电平由被动上拉决定，**不依赖任何芯片的上电行为**。
> 本板 GPIO8 **不接任何功能**（CHRG 因此落在 GPIO19）——充电时把 GPIO8 拉低会让复位释放瞬间读到一个
> 非预期组合，得不偿失。

## 四、外设硬件电路细节

### 4.1 32.768kHz 晶振（PA 的硬前提 + 续航的一号杠杆）
`docs/doc.md` §五.5 已定义该晶振的选型与匹配，本板**沿用同一料号与同一负载电容**（BOM 通用）。

| 项 | 定稿 |
| --- | --- |
| 晶振 Y1 | 同晶 XTF32032768JT00351011（3215，CL=12pF，ESR≤70kΩ，±20ppm 全温，立创 C37635363） |
| 负载电容 | 2×20pF C0G（0402，立创 C5137579） |
| 偏置电阻 | 5~10MΩ，**DNP** 预留焊盘 |
| 走线 | GPIO0/1 **两根等长对称、≤5mm**，下方与邻近**禁止走线/铺其他网络铜皮**，整块包地打过孔 |
| 远离 | 升降压开关节点（1.7MHz）、电感、电芯引线 ≥5mm |

> **为什么这颗晶振是本板的一号决策**：BLE 低功耗时钟若退化到**主晶振**，实测要多 **+3.33mA**（`tests/ble_sync` 实测）。
> 本板发射端在两次 PA 事件之间几乎全程轻睡，这 3.33mA **直接叠在整机电流上**——
> 广播档会从 ≈0.62mA 变成 ≈3.9mA，**500mAh 电芯的续航从 ≈34 天掉到 ≈5 天**。
> 反过来，晶振就位后要把固件的 `CONFIG_BT_LE_LP_CLK_SRC_*` 从 `MAIN_XTAL` 改回**跟随本慢时钟**
> （见 §十），否则硬件白装。

### 4.2 LIS3DH（运动检测）
```text
        3.40V ──┬── 0.1µF + 1µF ── Vdd
                └── 0.1µF ─────── Vdd_IO
                                    │
   GPIO14 (SDA) ──┬── 4.7k ── 3.40V │
   GPIO15 (SCL) ──┴── 4.7k ── 3.40V │
                  │                 │
              ┌───┴─────────────────┴───┐
              │  LIS3DH（LGA-16 3×3）   │
              │  SA0 → GND  ⇒ 地址 0x18 │
              │  CS  → 3.40V ⇒ I2C 模式 │
              │  INT1 → GPIO6（低有效） │
              │  INT2 → GPIO7（0Ω/DNP） │
              └─────────────────────────┘
```

| 项 | 取值 | 依据 |
| --- | --- | --- |
| 供电 | Vdd = Vdd_IO = 3.40V（1.71~3.6V ✅） | 不需要电平转换 |
| 总线 | I2C，**SA0 接 GND ⇒ 0x18** | 与驱动板约定一致（**CS 必须接高**才进 I2C 模式） |
| 量程 / 模式 | **±2g，低功耗模式（8-bit），ODR = 10Hz** | 10Hz 低功耗 ≈**4µA**；"有人动门"这个判据用不到高分辨率 |
| 中断 | **INT1，低有效，锁存（latched）** | 见下「两条硬性纪律」 |
| 门控 | **无**，常供电 | 待机 0.5µA、10Hz 采样 4µA，加开关不划算 |

> ⚠️ **纪律一：INT1 必须配成低有效**。四个唤醒源共用一次 ext1 调用，而 ext1 只有"任意低"或"任意高"
> 一种口径（**没有逐脚极性**）⇒ 按键与干接点天然低有效，**LIS3DH 必须跟着改成低有效**
> （`CTRL_REG6` 的 INT_POLARITY 位），否则运动唤醒进不了同一张 mask。
> ⚠️ **纪律二：INT1 建议配成锁存（`CTRL_REG5` 的 LIR_INT1）**，且**固件进中断后必须读 `INT1_SRC` 清锁存**。
> 漏读的后果是电平一直压在 ext1 上 ⇒ **反复唤醒、无法回睡**；配成脉冲则可能被深睡错过。

### 4.3 按键（OPEN / CLOSE / BOOT / RESET）
| 位号 | 键 | 接法 | 唤醒 | 说明 |
| --- | --- | --- | --- | --- |
| SW1 | **OPEN** | GPIO3 ↔ GND，100k 上拉 | ✅ ext1 | 主功能键：发 `OPEN` |
| SW2 | **CLOSE** | GPIO4 ↔ GND，100k 上拉 | ✅ ext1 | 主功能键：发 `CLOSE` |
| SW3 | **BOOT** | GPIO9 ↔ GND | ❌ | strapping 高电平靠芯片内部 45k 上拉；**严禁加消抖电容** |
| SW4 | **RESET** | EN ↔ GND（EN 另有 10k 上拉 + 1µF） | ❌ | 乐鑫推荐 RC |

> ⚠️ **不加消抖电容**（与驱动板同一纪律）：电容会把 ext1 的释放沿拖慢，深睡窗口内的电平翻转
> 可能被错过。**消抖一律做在固件**（采样 + 时间窗）。
> ⚠️ **键按住不放会怎样**：ext1 是电平触发，若固件在按键仍按下时就回睡，会**立刻再次唤醒**。
> 固件纪律：**回睡前必须确认所有唤醒源已释放**（或对该源做超时屏蔽）。
> **STOP / 长按关机**等派生操作由**固件**在 OPEN/CLOSE 上做时长判定，硬件不额外占用引脚。

### 4.4 外部唤醒输入座（3P：GND / RTCIO / VCC）
```text
   ┌─────────────── 3P 座 J4 ───────────────┐
   │ 1 GND        2 RTCIO          3 VCC    │
   └───┬───────────┬────────────────┬───────┘
       │           │ 1k             │ 100Ω
      GND          │                │
                   ├── 100nF ── GND │
                   ├── 100k ── 3.40V│
                   └── GPIO5（LP）  └── 3.40V
```
| 脚 | 网络 | 说明 |
| --- | --- | --- |
| 1 | **GND** | 与主板共地 |
| 2 | **RTCIO** = **GPIO5** | **LP 域**，可 ext1 深睡唤醒。100k 上拉 ⇒ **干接点（对地闭合）即低有效** |
| 3 | **VCC** = 3.40V（串 **100Ω**） | 供外部有源传感器用电；串阻把误插/短路电流封顶在 **≈34mA** |

> **定位**：给**外部干接点**（门磁、行程开关、外置按钮、闸机信号）或**低功耗外置传感器**留的入口。
> 极性约定：**低有效**（与按键、LIS3DH 同极性）⇒ 与其它三路共用 ext1 的"任意低"口径。
> ⚠️ **外部若是高有效传感器**，需要固件提供"外部输入极性"档位并**单独重挂 ext1**——不能与另外三路混用。
> ⚠️ **VCC 是常供的**：外接设备每多耗 100µA，500mAh 电芯的待机档就少 ≈57 天。
> ⇒ 说明书须写明"该座只允许接被动干接点或 µA 级传感器"。
> ⚠️ **这是用户可接触、且带线缆的连接器**：1k 串阻 + 100nF 抑制射频与 ESD；若走线较长，
> 再加一颗 0402 ESD 二极管（预留焊盘）。**不并入 EN 节点**（即该座**不能把设备从"关机"态唤醒**，
> 只能唤醒已经上电的深睡态）；如需它兼作开机，把一路二极管并入开机网络——本板**不预留这个位**。

### 4.5 WS2812B-2020-V6 指示
- **1 颗（D1）+ 1 颗 DNP（D2）**：D1 贴在**唯一可见面**；D2 为可见性冗余（实测不够亮/角度不足时补贴）。
- **常供 3.4V、无门控**（依规格书：静态电流 ≦1µA、供电 3.3~5.3V、上电零闪）。
- **睡眠不亮灯由固件保证**：进睡前必须发一帧全黑并**停止发送**（灯珠锁存末态）——**无硬件兜底**。
- DIN = **GPIO18**，串 **300~470Ω**（波形整形/EMC；低于 100Ω 边沿过陡易辐射）。规格书称外围不需要元件 ⇒ 串阻**可选**，另留 0Ω 位。
- VDD 就近 **0.1µF** 旁路；**不加就近大容量储能电容**（与驱动板同口径——本板单颗灯珠全亮仅 36mA 阶跃，与驱动板 108mA 的灯带不是一回事）。

**灯语（D1/D2 同色）**

| 状态 / 事件 | 颜色 | 说明 |
| --- | --- | --- |
| 深睡 / 关机 | **灭** | 发全黑后停发 |
| 广播中（常播档） | **灭** | ⚠️ **不做心跳闪、不做常亮**——见下方"灯的成本" |
| 上电自检 | 绿闪 1 次 | 「已上电 + PA 已起」 |
| 发出 OPEN | **绿闪 1 次** | 与驱动板"绿=运行"对齐 |
| 发出 CLOSE | **蓝闪 1 次** | |
| 发出 STOP | **红闪 1 次** | |
| 收到按键但未发出（PA 未起） | 红闪 2 次 | |
| 低电（可配阈值） | **红闪 2 次**（事件驱动，非周期） | ⚠️ **不做周期告警** |
| 充电中 | 橙慢闪（或由 D3 硬件灯承担） | |
| 故障 | 红闪码 | 码表待补（见 §9.2 #10） |

> ⚠️ **灯的成本是与 PA 发射同量级的**：一次 20ms 的闪灯、单色低亮度（≤32/255）约 **0.03 mA·s**，
> 而**一次 PA 发射是 0.134 mA·s**（`C_TX` 实测）。⇒ **亮一次灯不比发一帧便宜多少**。
> 纪律：**只做事件反馈**，禁止常亮、禁止心跳、禁止高亮度——**全白单次 20ms ≈0.7 mA·s（3×36mA），是 `C_TX` 的 5 倍**。
> ⚠️ **不做周期心跳**：驱动板用 D3 表达"工作/睡眠"，本板没有市电，任何周期性光输出都会直接缩短续航。

### 4.6 电池电压采样
| 项 | 值 | 说明 |
| --- | --- | --- |
| 分压 | **1M + 1M，1%**（比值 0.5） | 4.2V→2.1V，3.0V→1.5V，落在 ADC 12dB 档（≈0~3.1V）安全区 |
| 滤波/电荷池 | **100nF** 对地 | 源阻抗 500kΩ ⇒ **这颗电容是必需的**（给 ADC 采样开关提供低阻电荷源） |
| 常耗 | **2.1µA** | 占待机档 ≈35µA 的 6%，可接受（见下注） |
| 采样时机 | 固件周期性读（如 1min 一次） | 与电池"分钟级"的电压变化相比，采样率毫无压力 |

> **为什么不门控分压**：驱动板门控是因为不门控要 **222µA**；本板分压只有 **2.1µA**，
> 而门控要走"高边 P-MOS + 电平搬移"至少 4 个器件（**低边门控会把 ADC 节点抬到电芯电位，绝对禁止**）。
> ⇒ 用 4 个器件的失效率与占板去换 1µA，不划算。**明确接受这 2.1µA**。
> （若要减半，把两个电阻同时加倍到 2M2，代价是源阻抗升到 1.1MΩ——仍需 100nF，抗扰度下降。）

### 4.7 Type-C 接口电路
| 项 | 做法 | 原因 |
| --- | --- | --- |
| CC1 / CC2 | 各串 **5.1kΩ 下拉到 GND** | 标识 UFP 受电设备；漏掉则 C 口线不供电 |
| VBUS | 只进 **CL4064M**（见 §2.1） | **不进 DCDC 输入**（LN3440 VIN 绝对最大 6.5V） |
| D+ / D− | 加 ESD 阵列（USBLC6-2SC6），靠近连接器；走 90Ω 差分、等长、少过孔 | 热插拔 ESD + 信号完整性 |
| D+/D− 去向 | **GPIO12 / GPIO13**（模组的原生 USB 脚） | 给 ROM 的 USB-Serial-JTAG 下载留通路（固件可不启用，见 §十） |
| 电源路径 | **无**：USB 只管充电，系统永远吃电芯 | 见 §2.1 的两条理由 |

### 4.8 唤醒源汇总与 ext1 口径
| 唤醒源 | 引脚 | 极性 | 机制 |
| --- | --- | --- | --- |
| OPEN 按键 | GPIO3（LP） | **低** | 按下 = 接地 |
| CLOSE 按键 | GPIO4（LP） | **低** | 按下 = 接地 |
| 外部干接点 | GPIO5（LP） | **低** | 对地闭合 |
| LIS3DH 运动 | GPIO6（LP） | **低** | `CTRL_REG6` 配低有效 |
| （预留） | GPIO7（LP） | 低 | 第二唤醒输入 / INT2 |

> **四路同极性 ⇒ 一次 `ext1` 全覆盖**：mask = GPIO3|4|5|6，口径 = **"任意低"（ANY_LOW）**。
> ESP32-C6 的 ext1 **没有逐脚极性**，所以"统一低有效"不是风格选择，而是**接口约束**。
> ⚠️ 唤醒后必须**先读 INT1_SRC 清 LIS3DH 锁存**、并**等按键释放**再回睡，否则会反复唤醒（§4.2 / §4.3）。

## 五、功耗与续航
> 本文两档口径与 `docs/doc.md` §六、`docs/wireless_wakeup_options.md` 一致，**报指标必须注明档位**。

### 5.1 两档定义与实测模型
```text
广播档   I ≈ f_板 + C_TX / itvl      C_TX = 0.134 mA·s（C6 实测）
待机档   I ≈ 各常耗项之和（深睡，不发广播）
```
> ⚠️ **发射端没有 skip 自由度**——它是发送方，每个周期事件都必须发，所以
> `C_TX/itvl` 这一项**与接收端用多长的 T 无关**。发送端要省电，只能**改自己的 itvl**
> （`code/README.md` 记为待做的优化），改 T 只省接收端。

### 5.2 预算表（@电芯侧）
**待机档（深睡，"关机"）**

| 项 | 电流 | 说明 |
| --- | --- | --- |
| LN3440 输入静态 | **16µA** | 手册 typ；**本档最大单一项** |
| ESP32-C6 深睡 + 32k 晶振 | ≈**10µA** | C6 深睡 typ 7µA + 晶振 ≈1~3µA |
| LIS3DH（低功耗 10Hz） | **4µA** | 深睡期间仍在采样，也是唤醒源 |
| 电池分压 1M/1M | **2.1µA** | §4.6 |
| WS2812 静态 | ≤**1µA** | 已发全黑后的锁存态 |
| CL4064M（无 USB） | <**1µA** | 电芯漏电 |
| **合计** | **≈35µA** | 判据见 §9.2 #6 |

**广播档（常播，240ms）**

| 项 | 电流 | 说明 |
| --- | --- | --- |
| `C_TX / itvl` | **0.558 mA** | 0.134 mA·s / 0.24s |
| 芯片轻睡地板 | **34µA** | `docs/doc.md` 口径（晶振就位后） |
| 本板常耗（DCDC+LIS3DH+分压+灯） | **≈23µA** | 见上表除 ESP32 外各项 |
| **合计** | **≈0.62mA** | 判据见 §9.2 #7 |

> ⚠️ **若晶振缺席，本档要 +3.33mA（≈3.9mA）**——见 §4.1，这是本板最重要的单点决策。
> ⚠️ `f` 的板级部分（芯片 34µA + 板级）是**假设值**，`C_TX` 是**实测值**；两者都必须上板复测。

### 5.3 发射间隔（itvl）与续航
`I_广播 = C_TX/itvl + f_板`，其中 `C_TX = 0.134 mA·s` 是**实测**、`f_板 = 0.057 mA` 见 §5.2。

| 发送端 itvl | 纯广播 `C_TX/itvl` | 地板 `f_板` | **整机电流** | 地板占比 | 200mAh | 300mAh | 500mAh |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| **240ms**（现固件） | 0.558 mA | 0.057 mA | **0.62 mA** | 9% | **13.5 天** | 20 天 | **34 天** |
| **1 s** | 0.134 mA | 0.057 mA | **0.19 mA** | 30% | 44 天 | 65 天 | **109 天** |
| **1.5 s** | 0.089 mA | 0.057 mA | **0.15 mA** | 39% | 57 天 | 85 天 | **143 天** |
| **5 s** | 0.027 mA | 0.057 mA | **0.084 mA** | 68% | 99 天 | 149 天 | **249 天** |
| 深睡（不广播） | — | 0.035 mA（= §5.2 待机档） | **0.035 mA** | 100% | 8 个月 | 1.0 年 | **1.6 年** |

**约束① —— itvl 决定"远程唤醒时延的下界"**
接收端 `T = per_adv_ival × (skip+1)`，而 `skip ≥ 0` ⇒ **`T ≥ itvl`**。
⇒ 发送端把 itvl 拉到 1 s，系统**不可能快于 1 s 唤醒**；拉到 5 s 就不可能快于 5 s。

| itvl | 接收端可达的 T 集合 | 现固件的 `SENDER_T_ACTIVE_MS = 500` | 现固件的 `SENDER_T_IDLE_MS = 3000` |
| ---: | --- | --- | --- |
| 240 ms（现状） | 240/480/720 … ms | ✅ 实得 480 ms | ✅ 实得 3120 ms |
| **1 s** | 1/2/3 … s | ❌ **档位失效**（只能 ≥1 s） | ✅ **实得 3000 ms（比现状更准）** |
| 1.5 s | 1.5/3/4.5 … s | ❌ 失效 | ✅ 实得 3000 ms |
| 5 s | 5/10 … s | ❌ 失效 | ❌ 只能 5000 ms |

**约束② —— 改 itvl 要重建周期广播**
接收端会失步并重新扫描，实测**建链 ≈714 ms**（`tests/ble_sync/docs/02` §3.3），期间链路不可达。
⇒ itvl **适合"出厂静态配置"**，不适合"运动时快、静止时慢"的频繁切换。
（接收端的 skip 同理，改一次赔 0.5~1 s 空窗，见 `code/README.md` §13。）

> ✅ **`1 s` 是本表的一个自然折中**：整机 0.19 mA（比现状省 3.2 倍），且接收端的 **1 s / 3 s 两档都能精确落点**（3 s = skip 2），量化误差比现状的 480/3120 ms 更小；代价是**远程唤醒时延下界从 0.48 s 抬到 1 s**。
> ⚠️ **地板占比随 itvl 单调上升**：240 ms 时地板只占 **9%**（§5.2"待机档不是续航杠杆"的结论在此成立），到 **5 s 时占 68%** ⇒ **只有长间隔档才轮到"抠 LN3440 的 16µA"**。两个结论是同一个式子的两端，不矛盾。
> ⚠️ **参数合法性**：`per_adv_ival` 必须是 **1.25 ms 的整数倍**（240/1000/1500/5000 全部合法）；`sync_timeout` 必须 **> T**（`tests/ble_sync/docs/02` §4.4 前提 3）。
> ⚠️ **"常播"与"小电芯"不可能同时成立**：常播档电流由 `C_TX/itvl` 主导，**与板级设计无关**——省不掉，只能拉长 itvl 或改为按需广播。⇒ §9.1 #1。

### 5.4 灯的功耗纪律
见 §4.5 末注：一次低亮度闪灯 ≈**0.03 mA·s**，与 `C_TX`=0.134 mA·s 同量级。
⇒ 常亮（哪怕只有 1mA）会把广播档的续航砍掉一半以上，**本板禁止任何形式的常亮/心跳**。

## 六、布局与机械（要点，尺寸待定）
1. **天线净空是第一位**：ESP32-C6-MINI-1 的**天线端必须悬出板边**，且**远离电芯、金属壳体与手握位置**。
   手握会显著失谐——遥控器的天线要放在**远离按压区的那一端**。
2. **电芯占位与走线**：电芯引线（特别是负端）与天线区、晶振区、LIS3DH 保持距离；电芯下**不走敏感信号**。
3. **LIS3DH 的安装方向是功能的一部分**：加速度计的轴向决定"运动"的判据，**结构定下后必须同步固件的轴选择与阈值**（§9.2 #4）。
   芯片要**刚性固定在板上**（不要垫软胶），否则感知的是"壳在动"而不是"板在动"。
4. **升降压环路面积最小**：L1~L2、VIN 输入电容、VOUT 输出电容三者的回流路径要短；开关节点的铜皮**不要外扩**（1.7MHz 的辐射源）。
   电感与开关节点**远离**LIS3DH、晶振与天线。
5. **晶振区包地**：见 §4.1，与驱动板同一纪律。
6. **按键在人机侧**：OPEN/CLOSE 放按压面，BOOT/RESET 放侧面或背面（避免误触）。
7. **Type-C 与 3P 外部座**：插拔受力方向与结构件配合；丝印必须标**引脚序**（尤其 3P 座的 VCC）。
8. **板厚/层数**：本板信号简单、无大电流，**2 层板即可**（无电机斩波回流、无大电流环路）；
   若为天线净空与地完整性改 4 层，按 §四 的地纪律重做叠层评审。

## 七、接口与接线规范
1. **Type-C**：仅用于**充电**与（可选）原生 USB 调试。⚠️ **不能通过它给外部供电**。
2. **2P 电池座**：1S 锂电（**必须带保护板**）。⚠️ **无防反接**，插前确认极性。
3. **调试串口 4P（GND / GPIO16 / GPIO17 / 3.4V）**：与驱动板**引脚序相同**，同一块 USB-UART 小板通用。
   ⚠️ 该座带**常供 3.4V**——**不要与驱动板的同类座同时接到同一个适配器**（两个 3.4V 源会互灌）。
4. **外部唤醒输入 3P（GND / RTCIO / VCC）**：
   - RTCIO 为 **GPIO5（LP 域）**，**干接点对地闭合**即触发（低有效）。
   - VCC = 3.40V 经 **100Ω** 限流，**只允许接被动干接点或 µA 级传感器**。
   - ⚠️ 该座极性若插反会把 VCC 短路到 GND（由 100Ω 限流在 ≈34mA）；**座子选防呆型号 + 丝印标序**。

## 八、首次上电检查清单
1. 未上电：万用表确认**电芯极性**（电池座无防反接）。
2. 未上电：确认 **GPIO8 的 10k 上拉已贴**（漏贴会影响启动，且绝不能被拉低）。
3. 未上电：确认 **I2C 的 4.7k×2 已贴**（漏贴则 GPIO15 浮空 ⇒ strapping 无来源）。
4. **32.768kHz 晶振已贴装、负载电容正确**；上电后确认 RTC 时钟源为 **XTAL32K 而非 RC 回退**
   （启动日志出现 `32.768kHz XTAL not detected` 即为回退）。
5. **USB 单独供电**（先不装电芯）：确认 3.4V 轨**不出现**、充电器不工作——本板轨不来自 VBUS，属正常。
6. 装电芯（限流电源 0.5A 串入首测）：测 **3.40V 轨**（判据 3.35~3.45V）与**静态电流**（判据 ≈35µA，§9.2 #6）。
7. 先烧固件、确认串口日志正常，再装 LIS3DH 与 WS2812（分步定位）。
8. **LIS3DH**：`i2cdetect` 读到 **0x18**；读 WHO_AM_I（0x0F）应为 **0x33**；确认 INT1 在**低有效**下能被 ext1 触发。
9. **按键与外部座**：逐个按下/闭合，确认 ext1 唤醒、且**松开后能回睡**（不反复唤醒）。
10. **充电**：插 USB，确认 CHRG 拉低、GPIO19 读到低、充电电流实测 ≈200mA；拔掉后电流回落。
11. 插上 USB 时确认**启动不受影响**（GPIO8 未被拉低）。
12. **射频覆盖**：在最终外壳/手握姿态下实测有效距离（天线净空是唯一变量）。

| 8 | **WS2812 指示** | DIN → GPIO18 | 发送端工程**当前不依赖 RMT/LED 组件**⇒ 需新增驱动与灯语（§4.5），并保证**睡前发全黑** |
| 9 | **串口控制台** | GPIO16/17（4P 座） | 现为 `CONFIG_ESP_CONSOLE_UART_DEFAULT=y` ✅ **与硬件一致**；`USJ` 保持关闭（IDF-6395 与 ROM 下载模式两条理由） |
| 10 | **PA 间隔** | 与硬件无关，但决定续航与**唤醒时延下界** | `SENDER_PA_ITVL_MS`（默认 240）直接乘进 `C_TX/itvl`；**同时它是接收端 T 的粒度**（`T ≥ itvl`，§5.3）⇒ 若调大到 ≥1s，`SENDER_T_ACTIVE_MS=500` 会失效、`SENDER_T_IDLE_MS=3000` 需落在 itvl 的整数倍上。Kconfig 注释需补这两条口径 |
| 11 | **STOP / 关机等派生操作** | 不额外占引脚 | 由固件在 OPEN/CLOSE 上做时长判定（长按、双键同按） |
| 12 | **深度睡眠档** | 无常开门控（§2.4） | 若实现"按需广播"，要保证睡前把 WS2812 发全黑、并把 LIS3DH 的锁存清干净 |
