
# 闭环步进驱动板（ESP32-C6，42步进电机背装方案）文档整理
> 定位：推拉门/智能窗帘闭环步进驱动，**超低待机功耗**，支持手拉检测唤醒、CAN组网，板载磁编码器，电机尾部背贴PCB方案，主驱动DRV8874×2。

## 二、供电架构：单级DCDC直供3.3V
输入：**DC 12~24V**，单级Buck输出3.35~3.4V（不使用LDO）
> 输入上限由 Buck 决定：**TPP363070 的 VIN 上限为 36V**，实际系统最高输入按 36V 计，推荐长期工作 ≤30V。DRV8874 的 VM 极限 40V 不构成瓶颈，**任何场合都不应以 40V 作为输入上限使用**。
> 设计理由：全器件电压工作区间3.0~3.6V，buck纹波+瞬态跌落叠加后最低≥3.15V；省去LDO，减少发热与BOM数量。
> 抬高输出至3.35~3.4V：补偿磁珠DCR压降（ESP32 TX峰值382mA ×0.1Ω≈40mV），模组端稳压落在标称3.3V附近，上限3.47V <3.6V最大额定。

### 2.1 电源树
```
DC输入12~24V → 入口100µF/35V液态电解（阻尼）
├─ TPP363070 → 3.3V骨干轨（3.35~3.4V）
│  ├─磁珠 +22µF +0.1µF → ESP32-C6-MINI
│  ├─磁珠 +10µF +0.1µF → KTH5701编码器
│  ├─10µF +0.1µF → SN65HVD231 CAN
│  └─LED / WS2812（P-MOS开关，上电默认断电）
├─[高边P-MOS门控·GPIO7] + 100k+8.2k分压 + 10nF → GPIO2 ADC母线电压采集
└─DRV8874×2：VM功率轨就近固态100µF/35V +10µF+0.1µF贴VM引脚
```

### 2.2 支路滤波分工
|支路|措施|类型|作用|
| ---- | ---- | ---- | ---- |

|ESP32-C6-MINI|磁珠+22µF+0.1µF，π型滤波|射频降噪|板上唯一射频器件，抑制Buck纹波、振铃，保护WiFi接收灵敏度|

2. DRV8874就近：CH SV101M350E5R8R4Z00ZZ固态100µF/35V，ESR30mΩ；备选Ymin VPXC0581V101MVTMLR

### 2.5 磁珠选型（ESP32与KTH5701共用同料号，减少BOM）
**选型要求**
- 阻抗：600Ω@100MHz，400kHz衰减约55dB；最低≥120Ω可用
- DCR ≤0.25Ω（硬上限0.4Ω），382mA压降≤95mV，保证芯片最低电压余量
- 额定电流≥0.7A，推荐≥1A

选定：MGLB2012M601T1R2（麦捷，600Ω，DCR 250mΩ，1.2A）
升级备选：BLM21PG601SN1（村田，600Ω，0.1Ω，1.5A）
> PCB预留0Ω电阻位：实测噪声达标可直接直通，省去磁珠，不用改版。

### 2.6 电容布局硬性规则
1. 0.1µF必须贴芯片电源引脚1~2mm内；大电容放其后。小电容处理高频边沿电流。
2. 电容GND就近打via，和芯片GND构成最小电流环路。
3. 磁珠**两侧必须放置电容**（π结构），防止磁珠与芯片内部电容谐振放大噪声。

## 三、地平面、回流与PCB布局（4层板，板厚1.2mm）
叠层：
- L1 顶层：信号+元件
- L2：完整GND地平面，仅过孔穿透，不开槽
- L3：电源层，3.3V全域铺铜+VM电机功率分区；Buck开关节点走L1/L4局部，不进电源层
- L4 底层：信号+元件（编码器、被动器件）

> 4层核心理由：电机PWM电流回流依托L2地平面，自动避开编码器敏感区域；2层板很难在编码器下方铺连续干净地。
> 铜厚：JLC标准外层1oz，内层0.5oz；大电流走线全部放在外层。天线区域四层全部挖空铜皮（L1/L2/L3/L4）。

### 3.1 回流与地设计纪律
- 电机大电流回流**星形汇聚到电源入口**，不穿越3.3V信号地平面。
- DRV8874功率地独立回流；编码器与主控区域保持完整地平面。
- DRV OUT1/OUT2电机相线，从板边缘布线，绕开板中心编码器区；交变磁场是编码器主要干扰源。
- 天线净空：ESP32-C6-MINI天线端悬出板边，远离42电机金属壳体（金属会屏蔽WiFi）。
- **L4走线下方（L3层）在编码器与晶振区域应铺GND铜并打缝合过孔**，避免参考面为电源层造成回流不连续。

### 3.2 32.768kHz 晶振布局要求（硬性）
- 紧靠 ESP32-C6-MINI 的 GPIO0/GPIO1 放置，走线尽量短（建议 ≤5mm）、**两根等长对称**。
- 晶振与负载电容**下方及邻近区域禁止走线、禁止铺其他网络铜皮**，整块做包地处理并打过孔。
- 远离 DRV8874 的 PWM 输出（LEDC 20kHz）与开关节点、电机相线、Buck 功率电感至少 5mm。
- 两侧负载电容的地要单独就近回到模组 GND，不可与功率地共用回流路径。

### 3.3 正反面器件分配（板背贴42步进电机尾部，机械限高约束）

✅ **正面（朝外）**

### 4.3 GPIO与外设设计要点
> 引脚类别（strapping / ADC1 / RTCIO）与各自的上电约束见本节前两张表，此处不再重复。

1. ADC 已无剩余通道（见上表），后续若要增加模拟采样，只能改走外部 I2C ADC。
2. 单 I2C 总线（GPIO22/23）：**仅接 KTH5701 编码器**（无第二路从设备）。
3. 引脚成对排布：IPROPI-1/2相邻（GPIO4/5）；DRV控制成对（10/11、14/15）；CAN三线集中在18/19/20。

## 五、外设硬件电路细节
### 5.1 母线电压采集（高边门控式）
VM母线经**高边P-MOS门控**（GPIO7控制）→ 100k+8.2k 1% 分压 → 10nF滤波 → GPIO2 ADC。

**标定数据**
- 分压比 = 8.2/(100+8.2) = **0.0758**
- 24V→1.82V；30V→2.27V；36V→2.73V；40V→3.03V（仅作极限参考，已超 Buck 上限）
- 源阻抗 = 100k∥8.2k = **7.6kΩ**（回退方案 1M+82k 为 76kΩ，驱动条件差 10 倍）

**为什么门控后要"降阻+降容"**
门控把"单次测量"与"平均功耗"解耦了，因此可以主动降低阻值换取速度与精度：

|量|公式|关键性质|
| ---- | ---- | ---- |
|建立时间常数|τ = **(R1∥R2)** × C|注意是**并联值**，不是 R1+R2|
|单次导通时间|t_on ≈ 5τ|建立到 0.3% 精度|
|单次测量能耗|E ≈ **0.35 × VM² × C**|**与分压阻值无关**|
|平均功耗|P_avg = E × 测量频率|只由滤波电容 C 与测量频率决定|

> ⚠️ 常见误算：τ 用的是**并联值**（R1∥R2）×C，不是 (R1+R2)×C。回退方案（1M+82k 配 100nF）的 τ 也只有 **7.6ms**（5τ≈38ms）。

**推荐设计点（100k + 8.2k + 10nF + 高边门控）**
|项|值|
| ---- | ---- |
|分压比|0.0758（24V→1.82V）|
|源阻抗|7.6kΩ|
|τ|7.6kΩ × 10nF = **76µs**|
|单次导通|0.5~1ms|
|单次测量能耗|0.35 × 24² × 10nF = **2.0µJ**|
|平均功耗 @1Hz|**2µW**|
|平均功耗 @10Hz|**20µW**|
|对比：不门控的 1M+82k|533µW（**降低 266 倍**）|

> **门控的收益边界**：令 0.35·VM²·C·f 等于不门控的 VM²/R_total，得临界频率 f = 1/(0.35·C·R_total)。
> 本设计（100k+8.2k，10nF）的临界频率 ≈ **2.6kHz**——即使每秒测几百次，门控仍然划算。
> 若保持 1M+82k + 100nF，临界频率只有 **26Hz**。**这是"降阻+降容"的第二个好处：把门控的适用范围拉宽约 100 倍。**

**低阻带来的附带好处**
1. ADC 源阻抗从 76kΩ 降到 7.6kΩ，引脚漏电流引入的静态误差等比缩小，固件标定更简单。
2. 门控 MOS 若失效短路，持续功耗 5.3mW（高阻版本为 0.53mW）——两者都可忽略，**失效模式安全**，测量功能不受影响。

> ⚠️ **只能门控高边，绝不能门控低边**：开关若串在 8.2k 下方，关断时上臂电阻会把 ADC 节点抬到 VM 电位（24V），超引脚耐压、读数失真并有损伤风险。
> ⚠️ **与过压保护互斥**：门控后固件采样存在盲区（长度取决于测量频率）；要用母线电压做硬件级过压保护就不能门控，过压必须由 TVS 等硬件兜底（见§五.8）。
> ⚠️ **两个选择是绑定的**：若改为**不门控**，分压必须同时改回 1M+82k（100nF），否则 100k+8.2k 持续耗 **5.3mW**，比原来还差 10 倍。
> ⚠️ **门控 P-MOS 选型**：接 24V 母线，**耐压须 ≥40V**（AO3401A 的 −30V 不够），栅极需 NPN 或小 N-MOS 做电平转换，器件待定。

### 5.2 WS2812/SK6812状态灯（2~3颗，默认贴2颗，预留第3颗）
- 供电经独立P-MOS开关（GPIO8），栅极100k上拉：**上电默认断电**，且该上拉同时用作GPIO8的strapping上拉。
- DIN=GPIO21串联100Ω电阻；3.3V供电为规格下限，固件禁止全白高亮，避免过载。
- ⚠️ **选型必须明确**：普通WS2812B的VDD规格下限为3.5V，3.3V属超规使用；应选 **WS2812B-V5 / SK6812** 等支持3.3V的型号。
- ⚠️掉电顺序：先拉低DIN，再关闭供电，防止ESD寄生漏电造成幽灵微光。
- DIN建议加对地下拉，避免MCU复位期间引脚浮空被干扰。

**颜色状态定义**
- 绿常亮：运行唤醒
- 绿慢闪：就绪待命
- 灭：深睡
- 红闪N次：故障码 1过流 /2过温 /3编码器失效 /4CAN掉线 /5DRV8874 nFAULT /6母线过低 /7行程标定缺失或失败（过流/过温由DRV8874 nFAULT上报）
- 蓝闪：CAN总线活动
- 黄：配网模式
- 白渐变：OTA升级
- 紫：手拉启动接管

### 5.3 CAN总线 SN65HVD231
Rs引脚GPIO19，10k上拉，上电默认进入睡眠（40nA）；固件拉低Rs进入正常工作模式（tWAKE≈3µs）。
- **CAN 不参与唤醒**：SN65HVD231 睡眠时**驱动器与接收器全部关断**，总线引脚高阻、**RXD 恒为高电平**，退出睡眠只能由控制器拉低 Rs（tWAKE≈3µs）。所谓"总线显性位唤醒"是 SN65HVD230 的 standby 模式才有的特性，本板不采用。
- 配套：RXD 在 GPIO20（非 LP 域），与"不唤醒"的定位一致；收发器睡眠期间与 GPIO3 的编码器 ext1 唤醒线完全解耦，互不干扰。
- 若未来确需 CAN 唤醒，属于**重新选型**（换收发器 + RXD 放回 LP 脚 + 重算待机电流），不在本设计范围内。
- 板载120Ω终端电阻；菊花链拓扑，**只在总线两端节点保留120Ω，中间节点拆除**（建议用焊桥/跳线实现，便于现场切换）。
- 所有节点必须共地，CANH/CANL 用双绞线，接口为 **3P（含 GND）**——2P 时节点共地只能依赖 DC 回路，跨电源组网共模电压无法保证（见§七.3）。

### 5.4 DRV8874 外围配置
除 IN1/IN2/nSLEEP/nFAULT 外，DRV8874 还有 PMODE / IMODE / VREF / R_IPROPI 四组必须处理的配置项，缺一不可：

|引脚|配置方式|取值/说明|
| ---- | ---- | ---- |
|PMODE|GPIO6，两片共用，**MCU 控制**|三态（低=PH/EN、高=PWM、悬空=独立半桥），**不用电阻配置死**——三档对照见下节|
|IMODE|**电阻 strap：20kΩ 对地**|逐周期斩波 + 过流自动重试（遇阻不需断电恢复）；四档对照与选值理由见下节|
|VREF|两片共用一组 **3.4V 轨 10k+22k 分压，经高边 P-MOS 门控**|设定斩波阈值 ITRIP，必须落在数据手册推荐范围内；**必须门控**——不门控常态耗 106µA，是整机待机预算的 1.7 倍，电路见下|
|R_IPROPI|每片一颗，对地|将IPROPI电流转成电压供ADC读取，1%精度|
|nFAULT|两片线与→GPIO17|⚠️ 线与后**无法区分是哪一片报故障**，只能判定"有故障"；若需区分需拆成两个GPIO|

**PMODE 与 IMODE（两个模式脚，均在 nSLEEP 上升沿锁存）**

PMODE 三态 —— 内部偏置为 **44kΩ 下拉 + 156kΩ 上拉到内部 5V**，因此**悬空稳在 ≈1.1V（0.9~1.2V 窗口）= Hi-Z 档**，"悬空即默认低"是误解；阈值 低 ≤0.65V、高 1.5~5.5V：

|PMODE|模式|用途（本设计定位）|
| ---- | ---- | ---- |
|低|PH/EN|**常态**：`EN=0` = Brake（低边慢衰减）⇒ IPROPI 连续可测，唤醒"先切 brake"也靠它|
|高|PWM|需要 Coast（高阻）时用，且**不必动 nSLEEP**|
|悬空|独立半桥|退路：每半桥独立控制／高边慢衰减／驱动两个独立负载，换算法不必重画板|

- **为什么由 GPIO 控制而不是电阻配置死**：换来"三档随时可切"——改模式 = nSLEEP 拉低 → 等 tSLEEP → 改 PMODE → 抬 nSLEEP。LEDC 走 GPIO 矩阵、任意脚可用，所以切到 PWM/独立模式时 GPIO11/15 也能出 PWM，**换模式不用改线**；电阻 strap 只能锁死一档，也没有"先设电平再使能"的时序能力。
- **代价**：占一个 LP 域脚（GPIO6，LP 域已用满）；切模式要过 tSLEEP+tWAKE，不是实时手段；**复位窗口内该脚是 Hi-Z**（LightSleep 期间电平保持，不受影响）。
- ⚠️ **纪律：固件必须先写 PMODE=0 再抬 nSLEEP**——只有此刻锁存到的才是 PH/EN 安全态（现有固件顺序满足，见 app_main → foc_motor_init → power_state_init）。
- 偏置电流（三态脚固有）：**拉低时驱动器要灌入 ~32~50µA**（内部 156k 上拉经此流入地），**拉高时驱动器要输出 ~113~150µA**（经内部 44k 下拉入地）；两片共用一根线，按片数翻倍。

IMODE 四态 —— **必须用电阻设定**（内部偏置 136kΩ 下拉 + 68kΩ 上拉，悬空≈3.33V）：

|R_IMODE|电流斩波|过流响应|nFAULT 覆盖|
| ---- | ---- | ---- | ---- |
|GND|固定关断时间|自动重试|仅过流|
|**20kΩ 对地（本设计）**|**逐周期**|**自动重试**|**斩波 + 过流**|
|62kΩ 对地|逐周期|**锁存关断**|斩波 + 过流|
|悬空|固定关断时间|锁存关断|仅过流|

- 选 20kΩ 的理由：推拉门/窗帘遇阻是**瞬态**，锁存档必须断电或 nSLEEP 复位才能恢复，现场不可接受；自动重试 + nFAULT 上报才能让固件判"堵门"。
- 偏置电流：清醒时 20kΩ 一路从内部 5V 吸 **~57µA/片**，靠 nSLEEP 关断内部稳压才归零（列入§9.2 待核实）。

**VREF 门控（必做）**
10k+22k 分压取自 3.4V 轨，常态耗 **106µA ≈ 0.36mW@3.4V（折算 24V 输入侧 ≈0.42mW）**——是整机 0.25mW 待机预算的 **1.7 倍**。**不门控，§六 的待机指标当场不成立。**

|项|做法|
| ---- | ---- |
|高边开关|**P-MOS（SOT-23，AO3401A 级别即可——挂在 3.4V 轨上，无耐压问题）**，串在 3.4V 轨与 10k 之间，两片 DRV 共用|
|栅极默认态|**100k 上拉到 3.4V** ⇒ 默认关断（VREF=0）|
|驱动|**NPN（MMBT3904）**：集电极接栅极、发射极接地；基极经 **10k** 接 **nSLEEP（GPIO16）**|
|逻辑|**GPIO16 高 = VREF 有效；GPIO16 低 = VREF=0**（与 nSLEEP 同相，上电默认 VREF=0）|
|固件|**零改动**：GPIO16 本就由 `power_state.c` 独占（见§五.6），深睡/故障态真正拉低 nSLEEP 时 VREF 随之归零|
|上板自检|`vref 1` 量 VREF ≈ **2.34V**；`vref 0` 量 **0V**。不归零 ⇒ P-MOS 没关断，待机预算破|

> ⚠️ 纪律：`power_state.c` 是 GPIO16 的**唯一写入方**——自检命令之外的任何模块不得碰它，否则 106µA 照烧。

**参数计算**
```
IPROPI(µA) = 负载电流(A) × A_IPROPI(µA/A)     A_IPROPI Typ = 450 µA/A
V_IPROPI(V) = IPROPI × R_IPROPI
ITRIP(A)    = V_VREF / (R_IPROPI × A_IPROPI)
```
示例（42步进典型 1.5A/相）：VREF 取 2.34V（3.4V 经 10k/22k 分压）→ R_IPROPI = 2.34/(1.5×450µA) ≈ **3.5kΩ 1%**，此时 1.5A 对应 V_IPROPI≈2.36V，在 ADC 量程内。
- IPROPI 对地并 10nF 滤波（过大将拖慢斩波响应）；DRV8874 内部对 IPROPI 有钳位，可保护ADC。
- ADC 读到的 IPROPI 既可用于**堵转/堵门检测**，也可作为FOC电流环的相电流反馈（低边采样）。
- ⚠️ 实际 ITRIP 与 R_IPROPI 需按最终选定的电机相电流额定值核算后定稿。

### 5.5 32.768kHz RTC 晶振
连接到 GPIO0（XTAL_32K_P）/ GPIO1（XTAL_32K_N），作为 RTC_SLOW_CLK 时钟源。

**选型（已定稿）**
|项|定稿|
| ---- | ---- |
|晶振 Y1|同晶 XTF32032768JT00351011（SMD3215-2P，32.768kHz，CL=**12pF**，**ESR≤70kΩ**（乐鑫硬性要求），常温±10ppm／稳定度±20ppm，−40~+85℃；立创 C39361295）|
|负载电容 C1=C2|富捷 FCC0402N200J500AT ×2（0402 NPO/C0G，20pF ±5% 50V；立创 C5137579）|
|匹配|C1∥C2 串联等效 = 20×20/(20+20) = **10pF** + 板级杂散 C_stray≈1.5~2pF → 有效 ≈ **11.5~12pF** ≈ 晶振标称 CL=12pF ✓|
|可调|实测频率偏高（负载偏轻）改 22pF（串联等效 11pF），偏低改 18pF；0402 NPO ±5% 同系列有货|
|偏置电阻|5MΩ < R ≤ 10MΩ，**DNP** 预留焊盘；不起振时优先查此位与负载电容|

> C_stray 按紧贴模组 GPIO0/1 的布局估算，晶振区包地（见§三.2）有助于稳定该值。

**为什么必须加**
深睡 RTC 定时精度从内部 RC 的 **±5%（≈±72分钟/天）** 提升到晶振的 **±20ppm（≈±1.7秒/天）**——"定时开关窗帘"与"手拉速度判定／位置推算"的前提，RC 时基无法支撑。

**固件配置（⚠️ 必须显式选，否则硬件白装）**
- `CONFIG_RTC_CLK_SRC_EXT_CRYS=y`（C6 的 `RTC_CLK_SRC` choice **默认是内部 RC**，不选就没有 ±20ppm）
- `esp_clk_slow_src_set(SOC_RTC_SLOW_CLK_SRC_XTAL32K)`（等价运行时写法）
- **BLE 低功耗时钟跟随本慢时钟**：`CONFIG_BT_LE_LP_CLK_SRC_DEFAULT=y`（不是 MAIN_XTAL——
  无晶振才退 MAIN_XTAL，实测代价 **+3.33mA**）。选对这颗晶振是无线唤醒（PA）能省电的前提。
- 保留晶振不起振时回退 RC_SLOW 的看门狗逻辑，并上报故障码；启动日志出现
  `32.768kHz XTAL not detected` 即为回退，说明晶振没起振。
- 不启用该时钟源时 GPIO0/GPIO1 可作普通 GPIO——**本板已按启用晶振设计，不可再作他用**。

### 5.6 睡眠与使能控制
**全部睡眠/使能控制脚一览**

|控制对象|引脚|睡眠/关闭电平|决定上电默认的外围|深睡时状态|
| ---- | ---- | ---- | ---- | ---- |
|DRV8874 ×2（nSLEEP）|GPIO16|低=睡眠（低有效）|10k 下拉|H桥断电|
|DRV8874 ×2（PMODE）|GPIO6|固件在抬 nSLEEP 前写 0 = PH/EN|内部 44k/156k 偏置（悬空=Hi-Z）|安全态（nSLEEP 上升沿锁存）|
|CAN 收发器（Rs）|GPIO19|高=睡眠|10k 上拉|睡眠 40nA|
|WS2812 供电（P-MOS）|GPIO8|高=断电|100k 上拉（兼 strapping）|断电|
|KTH5701 编码器|—|I2C 配置|—|1.4µA 基线／25µA 采样|
|Buck TPP363070|—|无 EN 控制|—|常工作（供 ESP32）|

> 上电瞬间全部外设处于安全状态。睡眠期间这些电平靠什么维持，**取决于 MCU 用哪种睡眠**：
> - **LightSleep**：GPIO **保持**睡眠前的电平 ⇒ 靠固件进睡前显式写入（`power_state` 的 PS_SLEEP 分支已先拉低 nSLEEP）；
> - **DeepSleep**：GPIO 浮空 ⇒ 靠外部上下拉维持（nSLEEP 10k 下拉、Rs 10k 上拉、WS2812 100k 上拉）。
> ⇒ **外部上下拉一个都不能省**（复位与上电窗口同样依赖它们），两种睡眠下都**不依赖 GPIO HOLD**。

**睡眠/使能脚能否合并成一根线？（结论：不合并）**

|候选合并|可行性|结论|
| ---- | ---- | ---- |
|两片 DRV8874 的 nSLEEP|已合并，两片永远同态|✅ 保留|
|nSLEEP ＋（Rs／WS2812）|❌ **极性相反**：nSLEEP 低=睡眠，而 Rs、WS2812 都是高=睡眠/断电。直接并线会得到"电机已断电、收发器却已唤醒"或反之的错误组合；加反相级（1颗2N7002+电阻）只为省 1 个 GPIO，不划算|不合并|
|CAN Rs ＋ WS2812 供电|⚠️ **极性相同，但会锁死状态组合**：两者都是"低=工作/供电"。合并后无法表达「手拉接管时灯要亮、CAN 保持睡眠」——而这恰是低功耗手拉唤醒后最常用的状态（唤醒收发器要付出 mA 级电流，是 µA 级待机的几十倍）|不合并|

> **结论**：硬件不合并，**统一控制放在固件层**——用 power_state 状态机编排（见§10.3），每个状态分别定义 nSLEEP／Rs／WS2812／编码器采样的组合；并线会永久丧失状态组合能力。
> 两条补充：① LP 域已被母线分压门控（GPIO7）占满，但省 1 个引脚的收益远抵不上并线的代价；② **WS2812 断电有先后顺序要求**（先拉低 DIN 再断电，见§五.2），必须由固件单独控制关断时机，不能与别的控制同步切换。

### 5.7 Type-C 接口电路
|项|做法|原因|
| ---- | ---- | ---- |
|CC1 / CC2|各串 **5.1kΩ 下拉到 GND**|标识为 UFP 受电设备；漏掉则 C 口线不供电、无法识别|
|VBUS|SS14 肖特基并入 Buck 输入（见§七.4）|与 DC 输入二极管反向隔离|
|D+ / D−|加 ESD 阵列（如 USBLC6-2SC6），靠近连接器|热插拔 ESD|
|D+ / D− 走线|90Ω 差分阻抗、等长、尽量短、少打过孔|原生 USB 信号完整性|
|VBUS 检测|由母线分压 ADC 读取（USB 单独供电时约 4.6V）|固件据此判断"无 DC 输入"|
> ⚠️ 固件：USB 单独供电时 VM≈4.6V，仅比 DRV8874 最低工作电压 4.5V 高 0.1V，**必须禁止使能电机**。

### 5.8 VM 母线保护
**风险机理**：传动必须可逆（消防逃生要求），深睡时 H 桥处于高阻（coast）；手动推拉时电机作发电机，两相绕组经体二极管整流回灌 VM，即 VM ≈ 24V + 反电动势。

**量级估算**（42步进反电动势常数 Ke ≈ 5~10 V/kRPM 线电压）
|手拉转速|反电动势|VM 峰值|判定|
| ---- | ---- | ---- | ---- |
|100 RPM|0.5~1V|≈25V|✅ 安全|
|500 RPM|2.5~5V|≈27~29V|✅ 尚可|
|1200 RPM|6~12V|≈30~36V|⚠️ 逼近 Buck 上限|

> 结论：**常规手拉速度下风险不大**，只有极快手拉（或低减速比直驱结构）才逼近 36V。是否加保护器件应**先实测手拉最大速度下的 VM 峰值**再定，不凭猜测上大规格器件。

**保护手段**
1. **TVS（SMBJ 系列）**：泄放能量、限制尖峰。
   ⚠️ 固有局限：TVS 钳位电压 Vc 必然显著高于其关断电压，24V 母线可用的器件 Vc 普遍在 **40~48V**，**高于 Buck 的 36V 上限**——所以 TVS 只能"减少能量、缩短超压持续时间"，**不能保证 Buck 绝对不超压**。规格应在实测后于 SMBJ26A~33A 之间定稿。
2. **母线电容吸收**：入口 100µF 电解 + 就近固态 100µF（已有）。
3. **固件快速刹车（最有效）**：编码器 INT 唤醒后，**第一步不是平滑启动，而是把 H 桥切到 brake（两下管导通、绕组短接）**，把反灌能量消耗在绕组电阻上，确认 VM 回落后再进入助动控制。要求唤醒路径尽可能短（LP 核可先于主核执行最小刹车序列）。
4. **输入侧自恢复保险丝**（按峰值电流选取），与防反接的三重兜底并列。

## 六、低功耗唤醒方案（推拉门/窗帘应用）
> 场景：绝大多数时间处于深睡，**手推门/手拉窗帘 → 编码器检测转动，触发EXT1唤醒，电机平滑助动接管**
> 机械硬性前提：传动机构必须可逆（可手推，back-drivable）；蜗轮蜗杆自锁结构不可用，断电必须可手动推动（消防逃生要求）

### 6.1 唤醒源汇总
|唤醒源|机制|引脚|待机功耗|
| ---- | ---- | ---- | ---- |
|编码器KTH5701|角度变化产生INT中断，ext1唤醒|GPIO3（LP）|5Hz采样≈25µA；25Hz≈113µA；检测延迟200ms/40ms|
|RTC定时|LP定时器 + XTAL32K（±20ppm）|无引脚|晶振振荡器增量待实测（见§九 待核实 #3）|
|外部干接点/按键|ext1 GPIO唤醒，需与编码器INT**合并唤醒线**|GPIO3（LP，共线）|0|
|**无线唤醒（BLE 周期广播 PA）**|周期同步 + 窄窗口，收包调度由 BLE 控制器自理；芯片须停**轻睡**（深睡下射频收不到）|不占引脚|**亚 mA**：`f + 0.16/T`（C6 实测模型）；T=0.48s→≈0.4mA，T=3.12s→≈0.11mA（`f` 待实测）|
|WiFi/ESP-NOW（**未采用**）|轻睡模式数据包唤醒|不占引脚|4.96 mA 地板（S2 实测，比 PA 差 20 倍以上）|

> **CAN 不参与唤醒**：唤醒源只保留"编码器 + RTC + 干接点 + WiFi"四项——SN65HVD231 睡眠时接收器关断、RXD 恒高，物理上无法产生唤醒边沿（见§五.3）。

> **无线唤醒已定为必要能力（PA），待机口径因此分三档**：
> ① **深睡档**（无线关 / 监听窗口超时回落）＝本表的 ≈10µA ≈0.25mW@24V，只能本地唤醒；
> ② **PA 监听档**（出厂默认上电即监听，窗口内可远程唤醒）＝**亚 mA**，按 T 分档；
> ③ 运行态（电机主导，同步保持以便收"停"指令）。
> ⇒ **"整机 0.25mW"仅指第①档**，写出厂指标时必须注明档位。
> 唤醒周期 T 可由发送端用指令动态调整（陀螺仪快/慢档），实现与验证见 `code/README.md` §13。
> 两条路线的实测对比、选型建议与前提（含本板 32.768kHz 晶振这一硬前提）见 **[wireless_wakeup_options.md](wireless_wakeup_options.md)**。

**整机待机总功耗 ≈ 0.25mW @24V**
|项|电流/功耗|折算功耗|
| ---- | ---- | ---- |
|ESP32 睡眠|**DeepSleep ≈10µA**；**LightSleep 待实测**（见§9.2 #13）|0.03mW（DeepSleep 口径）|
|KTH5701|25µA @3.3V|0.08mW|
|TPP363070 输入侧|6µA @24V|0.14mW|
|**母线分压（门控 @1Hz）**|**2µW**|**≈0**|
|**VREF 分压（随 nSLEEP 门控）**|**≈0**|**≈0**|
|CAN收发器睡眠|40nA|≈0|
> 不门控时母线分压是最大单项（68%），整机 **0.78mW**；两处门控后降到 **0.25mW**。
> ⚠️ **睡眠模式口径**：本表 0.25mW 按 **DeepSleep**（`esp_deep_sleep_start()`，唤醒即复位）计算。**板级"深睡"若改用 LightSleep**（唤醒不复位、GPIO 电平保持），ESP32 那一项要按实测重算——LightSleep 电流高于 DeepSleep，0.25mW **不再自动成立**。
> ⚠️ 表里两项门控（母线分压、VREF 分压）**都是必做项**，任一不门控本表即作废——VREF 不门控单独就加 106µA ≈ **0.42mW@24V**（见§五.4），比整表还大。

### 6.2 固件核心要点
1. INT唤醒后：**第一步切 brake 泄放反灌能量**（见§五.8），再读取编码器角度、防抖判定方向与速度，最后平滑启动电机助动。
2. 多圈位置跟踪、定期NVS保存位置；上电自学习限位（获得"零点=全关0%/满行程点=全开100%"两个端点；未标定前不执行任何开度指令）。
3. 进入深睡前：Rs拉高、KTH5701配置为唤醒采样，配置ext1外部唤醒。
4. RTC定时任务（开关帘、定时同步）依赖XTAL32K；晶振异常时降级并上报。
5. **VM电压低于阈值时禁止使能电机**（USB单独供电时 VM≈4.6V，接近DRV8874最低工作电压4.5V）。

## 七、外部接口与接线规范
1. **DC供电（2P）**
    - 12V/24V推荐，**上限36V（Buck VIN限制）**。**无防反接保护，反接直接烧毁器件**；三重兜底：防呆连接器、丝印警示、上电前万用表确认极性。
    - 电源额定电流 ≥电机相电流 ×2相 ×1.5裕量。
2. **步进电机4P（A+ A- B+ B-）**：两相四线双极42步进电机。
    - 辨相：万用表测电阻，导通为同一绕组；线色不可靠。转向错误交换任意一相+/-。
    - 六线电机：中间抽头悬空；八线电机串联/并联接法，固件电流参数对应修改。
    - ❌禁止带电插拔电机线，断电等待电容放电完毕。
3. **CAN 3P（CANH/CANL/GND）**：菊花链，双绞线，节点共地，两端120Ω终端电阻。
    - **为什么是 3P**：不引出 GND 时节点共地只能依赖 DC 回路，跨电源组网时共模电压无法保证落在 HVD23x 的 −2V~7V 内；补一根地线成本极低。
4. **Type-C**：ESP32原生USB，烧录、串口调试，**不能驱动电机**。USB5V通过SS14肖特基并入Buck输入，DC供电时二极管反向隔离，互不冲突。接口电路（CC 5.1k×2、ESD、90Ω差分）见§五.7。

## 八、首次上电检查清单
1. 未上电，万用表确认DC输入极性。
2. 电机四线绕组分辨正确，端子紧固。
3. 编码器磁铁安装到位，气隙1~3mm，同心无明显偏心。
4. **32.768kHz晶振已贴装，负载电容正确；上电后确认RTC时钟源为XTAL32K而非RC回退。**
5. **确认GPIO8上电为高电平**（用示波器看复位释放窗口），否则无法进入下载模式。
6. CAN总线所有节点共地，终端电阻仅总线两端。
7. 使用限流电源（0.5A）初次上电，观察电流、有无异常发热。
8. 固件先用小电流点动、低速试运行，确认转向与编码器读数方向一致，再提升工作电流。

## 十、控制与固件架构
> 项目代号 FocStepper。本板的硬件组合（2路PWM + 2路方向 + 两路低边电流采样 + 绝对角度编码器）既能做闭环微步进，也能直接支撑 FOC 三环。本节先固定框架与分工，具体参数待样机标定。

### 10.1 信号链分工
|控制环|硬件资源|说明|
| ---- | ---- | ---- |
|位置环|KTH5701 绝对角度（GPIO22/23）|绝对角度，上电即知位置，无需找零|
|速度环|角度差分|由位置环输出|
|电流环|DRV8874 IPROPI（GPIO4/5 → ADC）|低边电流采样，两相各一路；⚠️ **IPROPI 只给幅值、没有符号**（手册：电流反向时该通道 ILSx 计 0）⇒ 符号须由最近一次指令方向重建，过零点有死区|
|PWM|**LEDC ×2**（GPIO10/14 = PWM/EN）+ **2路方向电平**（GPIO11/15 = PH），**PMODE=低（PH/EN 模式）**|每相 1 路 PWM + 1 路方向；PH/EN 下 `EN=0` = **Brake（低边慢衰减）**，IPROPI 连续可测|
> **为什么用 PH/EN 而不是 PWM 模式**：按 DRV8874 手册真值表，PWM 模式（PMODE=高）下 `IN1=IN2=0` 是 **Coast (Hi-Z)**，手册明确 *"In coast mode, the current is freewheeling and cannot be sensed"* ⇒ 四路独立占空比会让 IPROPI **只在导通期有效**，堵转检测与电流环一起受损。PH/EN 模式下 `EN=0` 即 Brake（低边慢衰减），手册称其 *"allows for the motor winding current to be sensed in both the drive and brake low-side slow-decay periods"* ⇒ **电流连续可测**，慢衰减纹波也更小（对齐 §10.2"无异响"），LEDC 占用 4→2 路。
> 参考项目（eetree #4598）用 `StepperDriver4PWM` + `LowsideCurrentSense`，本板**刻意不照抄**：`LowsideCurrentSense` 绑定 MCPWM 定时器与三电阻采样，在本拓扑（LEDC + DRV8874 内部低边采样）用不了；`CurrentSense` 本身只是两个纯虚的抽象接口，本板自研 `IpropiCurrentSense` 实现（见 code/README §8）。

### 10.2 运行模式（按场景分档）
|模式|触发|实现要点|关注指标|
| ---- | ---- | ---- | ---- |
|手拉接管|编码器 INT 唤醒|**先 brake 泄放 → 判定方向与速度 → 电流环平滑助动**|唤醒延迟、无异响、无顿挫|
|闭环位置|CAN / WiFi 指令|位置环 + 速度环 + 电流环|定位精度、不丢步|
|保持|到位后|电流环给保持电流（可配置降至 30~50%）|温升|
|空闲|无指令|nSLEEP 拉低，H桥高阻|回到 µA 级待机|

### 10.3 状态机（power_state）
|状态|nSLEEP|CAN Rs|WS2812|编码器采样|灯色|
| ---- | ---- | ---- | ---- | ---- | ---- |
|深睡|低|高|断电|5Hz 唤醒采样|灭|
|唤醒接管|**高**|高（保持睡眠）|供电|25Hz|紫|
|运行|高|**低**|供电|25Hz+|绿|
|故障|低|按需|供电|保持|红闪码|

> 本表即§五.6「不合并」结论的落地依据：同一个状态下三个控制脚取值不同，硬件并线无法表达。
> ⚠️ **MCU 侧睡眠模式**：深睡档可由 **DeepSleep**（唤醒即复位）或 **LightSleep**（唤醒不复位、GPIO 保持）实现，**代码用 Kconfig `FOCSTEP_SLEEP_MODE` 二选一**（见 `code/README.md` §12）。两种模式下本表三根控制脚的**取值要求相同**，差别只在"电平由**固件保持**还是由**外部上下拉**维持"（见§五.6），以及唤醒后是否需要重新初始化（LightSleep 从睡眠点继续，DeepSleep 走 `app_main` 重跑）。

### 10.4 必须落实的安全逻辑
1. **VM < 6V 禁止使能电机**（USB 单独供电时 VM≈4.6V，逼近 DRV8874 下限 4.5V）。
2. 上电自学习限位；多圈位置定期存 NVS。
3. nFAULT 触发 → 立即拉低 nSLEEP，记录故障码并闪灯告警。
4. CAN 丢帧 / 总线关闭 → 上报故障码 4，不影响本地控制。
5. 晶振不起振 → 降级 RC_SLOW 并上报。

## 附录：备选 TMC2209 待机控制时序（仅评估，本板不采用）
> 引脚：STDBY、ENN、VREF；分 5 阶段，**退出待机寄存器会全部丢失，必须重配 UART 参数**

### 阶段1 初次上电（Power-On）
- STDBY：拉低0；悬空内部下拉默认低，直接进入正常模式
- ENN：拉低0；建议硬件10k下拉，防止GPIO高阻误关功率级
- VREF：设定有效值；UART模式可悬空，不能超过2.5V
> 上电寄存器默认IHOLD=0，需要尽快UART配置保持电流。

### 阶段2 运行期间（Normal Operation）
- STDBY持续低，ENN持续低，VREF有效电压；正常微步进运行。

### 阶段3 进入待机（Enter Standby，顺序不可颠倒）
1. 停止STEP脉冲，电机静止
2. 拉低ENN
3. 拉低VREF到0V
4. 拉高STDBY（最后一步）
> 拉高STDBY，芯片内部稳压断电，进入深度休眠，寄存器丢失。

### 阶段4 待机期间（During Standby）
- STDBY=1，ENN=0，VREF=0；VCC_IO保持供电；静态功耗约2mW@12V。

### 阶段5 退出待机（Exit Standby）
1. 第一步：拉低STDBY，内部电源上电，寄存器恢复出厂默认
2. 重写UART寄存器 IHOLD/IRUN/IHOLDDELAY等（**必做**）
3. 恢复VREF有效电压
4. ENN按需拉高/保持低电平

### 速查表
|阶段|STDBY|ENN|VREF|关键动作|
| ---- | ---- | ---- | ---- | ---- |
|上电|0|0|有效|下拉电阻防止误触发|
|运行|0|0|有效|正常驱动|
|进入待机|1|0|0|停电机→ENN→VREF→STDBY拉高|
|待机保持|1|0|0|VCC_IO供电，电机断电|
|退出待机|0|0|有效|拉低STDBY，**重配寄存器**|

> 核心陷阱：退出STDBY休眠，寄存器全部重置；不重写参数电机无保持力矩，无法锁轴。
